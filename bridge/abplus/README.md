## 2. 采样与时间语义

- 每个 worker 使用原版 root/template/episode 进程；fork 复制引擎状态，不用另写玩法模拟器。
- worker 将可见记录写入共享数组，actor 合批推理；引擎执行上一条记录的动作。因此 pending action 必须进入观察，局首执行空动作。
- rollout 满足预算后，按 worker 时间序列计算 GAE，再做 PPO；最后一条未拿到奖励的记录留待后续结算。
- 房间、楼层与整局终止语义不同；开门离开未清房不能被误记为清房胜利，换层也不能丢掉资源和历史状态。
- JSON、Lua/native ROW、FastRow、fork、批量 `play` 的一致性是接口回归；它们通过不等于策略能力通过。

## 3. 输入、动作与奖励

策略只接收玩家可观察信息。地图未知区、未发现隐藏门、怪物内部血量/AI、随机数和未来事件不得通过旁路进入输入。

地上拾取物走 Entity 编码；库存、主动、饰品和口袋槽位走对应字段。未知药效、Blind 身份等必须在所有派生通道一致处理。旧实体/库存 cap 与语义缺失是待修问题，详见接口规范。

移动、射击、炸弹、主动及药丸/卡牌构成现有动作头；合法性按游戏状态处理。新动作或新输入形状需单独实现与评估，不因图上出现就宣称已支持。

奖励由事件和 `config.json` 决定；整局奖励、教师分支打分、终止/截断和评估指标必须核对一致。PPO、全局价值及辅助 loss 的关系见架构文档，不在本文件复制公式或历史 combat-v2…v5 调参过程。

## 4. 训练与评估入口

以下是 Linux 沙箱内的入口示例，运行前检查路径、设备、资源占用和 `--help`；不是本次已经执行的训练命令。`PYTHONPATH` 指向当前源码的 `bridge/python`。

```bash
export SRC=/path/to/Isaac/rl
export PYTHONPATH="$SRC/bridge/python"
python "$SRC/bridge/python/train_tok.py" --help
python "$SRC/bridge/python/eval_tok.py" --help
```

正式训练复用已验证的运行脚本与配置，不在 README 拼一个缺少 teacher/CF/状态参数的“通用最快命令”。`--resume` 的累计计数与 `--game-hours` 的新增预算要分别核对；加载旧权重不保证新增结构初始输出等价。

冻结整局评估的基本入口：

```bash
python "$SRC/bridge/python/eval_tok.py"   --checkpoint "$MODEL" --mode run --workers 8   --seeds 2147490000:512 --out "$EVAL_OUT"
```

该命令只展示基本参数；使用匹配运行的引擎配置、空闲实例名称/端口及资源配额。无主动对照在同一检查点和种子块上加 `--no-active 1`，结果另存；不能覆盖正常组。

- 跟踪用 128 种子，候选正式比较用 512 种子；不同训练随机种子的复验另列。
- 报告平均过层、各层到达分布、超时/死亡、资源/道具行为及训练成本；分清确定性/采样策略和评估时的停滞规则。
- 保存逐种子结果，做配对差与置信区间；不要只比较一个最高点。无 D6 的 128 种子筛查不能宣称泛化问题全部解决。

## 6. 性能与共享机器

最近选定的复测配置为 **64 workers、1 ms polling、minibatch/micro=8192**；它是特定模型和共享主机条件下的已选配置，不是跨机器保证最快。历史测速证据在工作区 `temp/new-host-audit-20261019/`；候选记忆重算路径应单独复测，不能借用旧模型速度。

先看 CPU quota/绑核、GPU 所有者、容器内存和现有任务；区分 collect、actor inference、learner update 和教师分支开销。完整 teacher/CF 配方下测速，丢弃预热、重复基准、报告干扰。不能通过关闭主要机制或挤占他人任务制造“加速”。

## 7. 历史机制与边界

- A7/A8：重放返回受跨局 RNG、音源状态等影响；相同种子并不自动保证任意历史下精确返回。
- A19/A22：fork 和批量 `play` 在所测配置下通过逐步对齐；炸弹、地形更新、换房和恢复点必须纳入回归。
- B3/B16：历史引擎内存增长与 root 卡死有独立处理路径；不要仅因 child 完成就认为 root 已安全回收。
- B13/B38：GPU 并发与多进程流水有实现约束；使用当前脚本，不套用旧“一卡只能一训练器”作为永久结论。
