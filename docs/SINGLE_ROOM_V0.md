# 单房间战斗 v0：实现与实测

日期：2026-09-19。**用户复核后判定方向错误：这是自编规则射击原型，不是符合要求的以撒单房间模拟。停止作为项目成果推进，保留下面的旧实现/自测记录，不将其作为验收依据。**

## 2026-09-19 纠偏复核

### 错在哪里

旧版没有加载任何原版资源、房间或实体配置。`env.py:11–14` 写死 60 Hz、640×400 和两块岩柱；`env.py:43–55` 将 NPC 抽象成两个自编类型、统一生命 6；`env.py:150–186` 自行指定移动响应、弹速、发射间隔和三发扇形。`view.py` 用几何图形取代精灵/动画，`policy.py` 则专门解这些自编规则。自测通过和脚本清房是内部自洽，不是对以撒的有效性检验。

### 已实际读取的依据

1. **原版基础配置。** 本机 `config.a` 提取出 21 份 XML、3 份文本。`entities2.xml` 有 495 条实体配置。其 Gaper `10.1` 为 baseHP=10、collisionRadius=13；Horf `12.0` 为 10/13；Fly `13.0` 为 3/17、collisionDamage=0、gridCollision=walls；Pooter `14.0` 为 8/17、collisionDamage=0、gridCollision=walls。这已经反证旧版统一敌人参数没有来源。**这些是基础包值，尚未应用 DLC 覆盖，不宣称是 J460 最终值。**
2. **真实角色与场景图像。** `graphics.a` 提取出 2300 个 PNG；实际打开检查了 `character_001_isaac.png` 精灵表，且存在 Basement 背景、岩石/装饰和怪物图像。不能靠手画圆形替代已有素材，再将其当作以撒训练场。
3. **真实房间。** `rooms.a` 提取出 13 个 STB；其中 Basement 已用现成工具转成 XML，解析到 572 条 room，存在 13×7 等网格尺寸、门的位置与开关、每格实体 type/variant/subtype 和权重。仍需处理版本覆盖、特殊记录及网格到世界坐标转换，不能直接把这些网格数字当像素尺寸。
4. **实际战斗函数候选。** 用本地 REPENTOGON `EntityPlayer.zhl:607–608` 的 `GetTearMovementInheritance` 字节模式扫描 J460，只匹配到 VA `0x007AAEA0`，对应既有导出 [003AAEA0_FUN_007aaea0.c](../../analysis/j460/exports/j460-baseline/decompiled/03/003AAEA0_FUN_007aaea0.c)。已读该函数的向量投影/条件分支，并从本机映像读到所引用 `DAT_00baa304` 的 float 值约为 0.6。**唯一特征匹配是语义候选，不等于完成 J460 字段布局及运行行为验证；更不能把该常量直接当统一眼泪继承系数。** Player/NPC/Tear Update 的参考签名本轮未匹配，不能复用旧版地址。
5. **眼泪不是只有二维速度和 TTL。** 本地 `EntityTear.zhl` 列出 height、fallingSpeed、fallingAccel、tearFlags、knockbackMultiplier、tearRange 等状态；这是跨版本逆向线索，字段偏移不能直接移植到 J460。旧原型完全遗漏了这套机制。
6. **更新时钟不能混同。** Lua API 文档区分游戏更新回调 30 次/秒、渲染 60 次/秒，玩家更新回调又标为 60 次/秒。旧版将所有系统都按 60 Hz 写死，没有机制依据；下一版需按目标版本验证各子系统节奏，不能只机械地把 DT 改成 1/30。[回调文档](https://wofsauge.github.io/IsaacDocs/rep/enums/ModCallbacks.html)

本地资源与提取过程见 [分析区索引](../../analysis/README.md#2026-09-19-实际资源读取)。没有修改或启动原版游戏，没有在此轮继续扩写旧模拟器。

### 当前模型，不是原版参数表

- 房间 640×400 单位，空房或双岩柱；默认 2 个追踪敌人、2 个固定扇形射击敌人，种子改变初始位置和发射相位。
- 玩家半径 12、最高速度 165 单位/秒，平滑速度响应；6 个生命单位，每次受伤损失 1，45 tick 无敌窗口。
- 四向眼泪，360 单位/秒、间隔 12 tick、伤害 2；敌人生命 6。弹体最先碰墙/障碍/目标即消失，不穿透、不命中多个敌人。
- 追踪敌人速度 72，局部转向绕岩柱；射击敌人每 100 tick 发三枚扇形弹幕，弹速 125。
- 默认每步保持动作 4 个物理 tick；可视化以每 tick 采样控制。默认 3600 tick 超时。

这些是用于闭环的工程初值，尚未从原版轨迹拟合。暂不模拟泪高/落地、完整击退、敌人相互推挤、真实 NPC 寻路、道具协同、炸弹/主动道具、诅咒、探索或换房。几何绘图不是原版画面；两种通用敌人不能冒充已复刻具体原版怪物。

## 2. 观测与动作契约 v0

所有空间/速度数值使用房间单位与秒，数组为新分配的 `float32`，策略修改数组不会反向修改模拟状态。

| 观测键 | 形状 / 内容 |
|---|---|
| `player` | `(7,)`：x、y、vx、vy、半径、当前生命、可见无敌环布尔值 |
| `enemies` | `(N,6)`：类型、x、y、vx、vy、半径；仅可见实体 |
| `bullets` | `(M,6)`：阵营、x、y、vx、vy、半径；仅可见弹体 |
| `obstacles` | `(K,4)`：可见岩柱的左、上、宽、高 |
| `room` | `(2,)`：当前房间宽高 |
| `tick` | 已经过的模拟 tick |

实体数组是变长的；当前没有 padding、全局实体 ID、固定 spaces 或向量化张量包装。未来接训练库时需增加显式掩码及标准适配器，不能直接把原始字典交给要求固定 spaces 的训练器。

敌人精确 HP、射击倒计时、随机种子/RNG、弹体剩余寿命均不在观测中。渲染器也不读取这些字段。当前全房间可见，岩柱不做视觉遮挡；`visible=False` 和屏幕外实体被过滤，测试验证它们不影响当下观测与画面。这不是尚未实现的完整原版迷雾/遮挡规则。

`action = (move, shoot)`：move 为 0 停止、1 上、2 右上、3 右、4 右下、5 下、6 左下、7 左、8 左上；shoot 为 0 不射、1 上、2 右、3 下、4 左。斜向移动归一化；同时按相反移动键抵消，同时按多个射击方向时按上/右/下/左顺序选一个。

`reset(seed=...) -> (obs, info)`；`step(action) -> (obs, reward, terminated, truncated, info)`。清房/死亡是终止，达到时间限是截断；二者同 tick 时清房/死亡优先于超时，死亡优先于清房。结束后必须 reset，不能悄悄自动重开。[Gymnasium 返回值约定](https://gymnasium.farama.org/api/env/)

奖励仅用于后续训练：每造成 1 点伤害 +0.1、击杀 +1、受伤 -1、每物理 tick -0.001、清房 +5、死亡 -5；提前终止时只累计真正执行的 tick。`info` 保存 outcome、ticks、kills、damage_taken。规则策略不读取 reward、info 或环境对象，避免从评估真值获取优势。

python -m pytest -q -p no:cacheprovider

覆盖：种子与动作重放一致、重置清除状态、4 tick 步进等价于单 tick、9 个移动方向墙约束、岩柱阻挡与滑动、扫掠防穿透/最近命中、射击节奏与寿命、追踪与扇形发射、受伤/无敌/接触伤害、清房/死亡/超时、非法动作、隐藏状态不干扰观测、观测无可变引用泄漏、无头不导入显示库、串并行回合一致、键盘映射与暂停/重置 UI 循环。

UI 循环通过 SDL dummy 后端测试，没有打开用户桌面窗口或发送系统按键。实际显示器上的手动游玩体验尚待用户试用；离屏渲染已实跑并检查画面。

### 回合 smoke test

统一 seed 0–23；偶数为空房、奇数为双岩柱；最大 3600 tick；每动作 4 tick；2 个进程。每种控制器使用相同房间种子，但轨迹当然不同。

| 控制器 | 清房 | 死亡 | 超时 | 平均受伤生命单位 | 原始报告 |
|---|---:|---:|---:|---:|---|
| 站立不动 | 0/24 | 24 | 0 | 6 | [idle](../runs/idle-24.json) |
| 随机动作 | 0/24 | 24 | 0 | 6 | [random](../runs/random-24.json) |
| 规则控制器 | 24/24 | 0 | 0 | 0.2083 | [scripted](../runs/scripted-24.json) |

规则控制器该次运行耗时约 1.18 秒，聚合吞吐约 8783 物理 tick/秒、2203 环境 step/秒，包含启动进程、策略与观测开销。同一批 24 局另以串行运行，耗时约 1.60 秒；逐局 outcome、ticks、kills、damage、steps 和 reward 与并行报告完全一致。[串行报告](../runs/scripted-serial-24.json)。这些只是当前硬件和极小场景的单次测量，不代表稳定并行扩展效率或原版吞吐。

这一测试集同时承担开发 smoke test，**不是独立泛化测试集**。24/24 只能说明简单场景可被当前规则解出，不能宣称 RL 已达标、学到了策略或能迁移到原版。
