# Isaac RL：目标、观测边界与分阶段设计

更新：2026-09-23。**当前主线为Rust课程模拟器 + Ubuntu 128环境GPU PPO；原版J460保留作校准、可视化与迁移验收。** 原版2/4引擎训练已跑通但512局零清房；L2已正式长训，尚未稳定收敛，也没有原版迁移达标成绩。最新阶段和证据见[ENV_ARCHITECTURE.md §0.14](ENV_ARCHITECTURE.md#014-当前阶段与-claude-只读审查交接2026-09-23)。本文维护产品目标与边界，旧自编规则`isaac_room`不属于当前实现。

## 1. 已确认的产品目标

- 最终做能完成整局游戏的 AI，包含战斗、探索、资源管理、道具组合和路线决策。
- 第一阶段先让**单房间战斗能力达标**，不把全游戏内容复刻作为前置条件。
- 接受 sim-to-game：独立模拟器可以近似原版，价值由迁移到原版后的表现决定，不要求逐指令或逐帧轨迹相同。
- 推理时只有玩家能获取的信息。视觉识别或内存读取都可作为采集方式，包括可见怪物、实体碰撞形状、允许的属性、道具和已知地图；内存可读不等于策略可用。
- NetFix 与 RL 分开交付。原生网络回滚是否确定，不是独立训练场能否开工的必要条件。

## 2. 原始 sim-to-game 方案与当前实现

当前训练路径是 **Rust模拟器/Rayon批量环境 → GPU可见历史与rollout → PPO**，128环境共享模型；玩家/Monstro/炸弹及4种地形构成首期课程。原版路径 **J460 + Lua同步桥接 → Gymnasium → 原版输入** 保留作量具和验收，固定Isaac/无额外道具/Monstro场景用rewind重置、虚拟时钟关闭。Rust是机制移植子集，不是抽离原版二进制引擎。

```text
独立无渲染模拟器 ─┐
                  ├─ 可见性过滤 + 字段白名单 ─ PolicyObservation ─ 策略 ─ 合法游戏输入
原版采集适配器 ───┘                              ↑                     │
       │                                        └── 下一次观测 ────────┘
       └─ 完整真值 → 校准/奖励/验收记录（与策略输入隔离）

大量独立模拟器 rollout → 批量推理/学习 → 候选策略
候选策略 → 少量原版固定测试场景 → 差异分析 → 更新模拟器或训练分布
```

共享的是观测与动作的**语义契约**，不是要求双方使用同一种引擎或渲染器。Gymnasium spaces/Env 和 SB3 PPO 已接入并验证。当前只恢复房间入口快照，不声称能任意帧恢复；Lua 后生成的 Boss 在 rewind 后重新建场。当前combat-v1奖励为受伤−1、有效扣血命中+0.05、实际伤害/初始MaxHP、清房+3及速度奖金0～1、120秒超时−1；没有每秒罚分或额外死亡罚分。120秒为任务终止，剩余时间进入可见观测；旧奖励只作历史对照。

### 原版端已选 J460；REPENTOGON 仅作参考

当前 RL 与 NetFix 的目标都是 Repentance+ J460。REPENTOGON 参考代码的地址、布局与 Hook 不能直接混用；当前 worker 未加载 REPENTOGON。

## 3. “玩家可观察”必须成为可测试的接口

区分四层：引擎完整状态、当下允许观测、由过往允许观测形成的记忆、评估器使用的完整真值。只把中间两层送入 actor。

| 信息 | 策略允许接收 | 不应直接接收 |
|---|---|---|
| 玩家 | 可见 HUD、已知持有物、位置及允许的角色属性 | 当前不可见且不能由历史确定的内部值 |
| 敌人与弹幕 | 当下可见实体的位置、形状、类别、可见动作；允许的公开属性 | 隐藏/钻地实体的实时位置、内部 AI 状态编号、下一次攻击计时器、未来 RNG |
| 血量与效果 | 屏幕显示的信息或经确认允许的公开属性 | 无血条敌人的精确实时 HP 自动透传；应使用未知或基于历史的估计 |
| 碰撞信息 | 用户允许的可见实体碰撞形状/公开模板 | 隐藏碰撞体、完整世界碰撞列表；像素路径也不能假称拥有同等精度 |
| 道具 | 可识别外观、已知效果、已持有道具 | 问号/未知道具的内部真实 ID、尚未揭示的随机结果 |
| 地图 | 当前可见几何、已经揭示的地图，以及此前看到的内容 | 未探索房间的怪物、奖励、完整关卡拓扑 |
| 历史 | 自身过去动作、过去允许观测及基于这些信息的推断 | 从隐藏实时状态刷新“记忆” |

上述细项是建议白名单；特殊诅咒、遮挡、道具揭图等规则还需要确认并逐项落地。道具合法揭示的信息应随能力扩展，不应一律禁用。

**可见性不等于实体中心落在摄像机范围内。** 还要考虑实体实际显隐、遮挡、屏幕裁切和当前游戏效果。像素框、渲染精灵边界、碰撞形状是三个不同概念。

建议 `PolicyObservation` 包含：

- 环境步/观测时间、上一动作持续时间；
- 玩家与 HUD、已知库存；
- 可见实体集合：局部跟踪 ID、类别、相对位置/运动、碰撞形状、允许属性；
- 可见障碍/门、已揭示地图；
- 各字段的已知/未知掩码、观测误差与延迟信息。

不使用内存地址、随机种子或可推导隐藏信息的实体 ID。实体数量、排序、padding、动作掩码也必须只依赖允许信息。速度可以由历史估计；内存精确值是否进入结构化版本需列入白名单。视觉版与结构化版分别报告感知误差，不能把二者成绩直接混为一谈。

**接口验收：**构造允许观测历史相同、隐藏状态不同的成对场景；actor 的输入、动作掩码及记忆初始化应完全一致。训练奖励/特权 critic 若使用真值，必须位于独立通道，不能通过上一奖励、日志特征或 recurrent state 回流到 actor。特权 critic 是可选研究方案，不是默认已选配置。

## 4. 动作、时钟与 reset

- 动作映射到原版合法移动、射击和阶段允许的道具输入；不能用直接设置速度、位置或生成眼泪代替真实控制并据此宣称迁移成功。
- 一个环境 step 推进确定的逻辑时间；把观测延迟、动作重复和输入生效延迟显式记录。墙钟睡眠不等于原版已经推进对应帧数。
- 分清死亡/清房等任务终止与超时截断；reset 必须确认敌人、玩家、道具及场景实际就绪。
- 首轮训练子集只实现需要的角色、敌人和道具组合。特殊输入类型和全道具联动随课程扩展。

## 5. 独立模拟器优先还原什么

优先保证会改变动作选择的关系：移动响应、惯性与碰撞，弹幕速度/尺寸，射击节奏，敌人攻击前摇与模式，受伤和无敌窗口，障碍遮挡。资源文件、公开机制和反编译为参数/逻辑提供线索；真实受控轨迹用于标定，不能只凭静态文档认定参数正确。

短轨迹比较用于找误差来源，最终以相同任务上的策略迁移表现判定。随机化速度、碰撞尺寸、反应延迟和感知误差的范围应来自采样或明确实验，不应随意扩大。领域随机化是一种方法，不是迁移保证。[动力学随机化研究](https://arxiv.org/abs/1710.06537)

采样应记录游戏版本、房间/敌人配置、允许观测、动作、生效时刻和结果。解包纹理/动画主要帮助识别与标注，不意味着已经得到可运行的完整行为模型。

## 6. 并行训练怎么做

1. **独立模拟器：**先基准测试单实例，再采用批量环境或多进程 rollout；各环境独立 RNG、episode 状态和策略记忆。需要神经推理时可合批送 GPU，学习器消费轨迹。
2. **原版环境：**先单实例验证观测、输入、重开和时间推进，再测少量隔离实例的吞吐。配置、存档、IPC、窗口焦点和显存都是需要实测的约束，当前没有“原版无头几百开”的证据。
3. **训练数据：**记录策略版本、环境配置和终止原因，控制过期轨迹；不同进程不能共享 actor 的隐藏状态。
4. **规模决策：**以环境步/秒、有效样本/秒、GPU 等待和原版迁移提升决定是否扩容；当前不引入分布式集群脚手架，也不承诺并发数。

## 7. 从单房间到完整流程

| 阶段 | 产出 | 验收重点 |
|---|---|---|
| 0：任务与采集闭环 | 明确首批场景、观测白名单；原版可重置/采样/执行动作 | 同步语义、合法输入、信息隔离；尚不要求策略强 |
| 1：基础战斗 | 走位、躲弹、追踪射击；少量敌人/障碍/常见武器 | 在原版完成单房间任务，受伤与耗时可测 |
| 2：房间泛化 | 多布局、混合敌人、选定道具变化 | 留出房间/种子/敌人组合；评估零样本迁移及固定预算微调 |
| 3：连续房间 | 探索、地图记忆、资源与奖励选择 | 连续房间累积风险、资源利用和恢复能力 |
| 4：完整游戏 | 跨层决策、道具组合和 Boss 路线 | 全局通关率与不同构筑泛化；是否分层策略另行比较 |

单房间不是只在训练布局中无伤，也不是只会避弹。需要同时考察清房率、受伤量、清房时间和动作预算，防止奖励鼓励无限绕圈。训练/验证/测试按布局与组合划分，不能仅换一个随机种子就声称泛化。

建议比较随机或脚本基线、仅原版训练、仅模拟训练、模拟预训练后固定原版预算微调；匹配交互预算和推理频率。报告测试样本量、置信区间及失败类型，保留独立最终测试集，不能把反复用于校准的场景再当未见测试集。

## 8. 原版校准和扩展前仍需选择

1. 原版基准使用现有 J460，还是单独维护 REPENTOGON 兼容环境？不应为研究擅自替换当前安装。
2. 第一批房间、敌人、角色和道具范围，以及“达标”的清房率/受伤/耗时标准。
3. 首版已确认采用独立模拟和可见结构化状态；后续是否增加像素识别/感知误差层仍待选择。
4. 可用训练硬件/时间预算，以及单房间之后的目标通关终点。
