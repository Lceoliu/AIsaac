# 研究原则与实验判据

更新：2026-10-21。保留历次讨论仍有效的原则；旧硬件瓶颈、实验排期和模型效果不作为永恒结论。数值只在[实验总账](../bridge/abplus/EXPERIMENTS.md)维护。

## Bitter Lesson 与输入完整性

- 优先通用学习、数据与计算，而不是不断增加手写玩法答案。先确保任务需要的信息可观察、可区分、可记忆，动作可执行。
- “减少人为偏置”不等于不做测量：字段语义、可见性、数量截断、状态更新与算力预算必须明确。
- 参数更多、token 更多或历史窗口更长都不是收益证明；将表示能力、梯度信用分配、记忆陈旧度、数据分布分开验证。
- 训练起点可覆盖真实角色、起手道具和资源变化；正式验收仍保留自然开局，不用奖励规则替代泛化。

## 经验与因果判断

- 将已观察事实、解释假说与待测方案分开。C98 的事后去 GRU 失败不能证明从零必须有 GRU；单个 no-D6 结果不能概括所有权重和开局。
- 先修数据语义与监督对齐，再扩大搜索或 loss 权重；旧缓存经当前 writer 重投影不等于重新编码过去观察。
- 教师成功不等于策略学会：用固定留出恢复点、自主闭环行为和正式评估检查内化。分支质量目标与当前策略价值目标不是同一件事。
- 保留负结果、反例和修正后的结论，删除已经失效的排期与逐次猜测，不删除失败实验本身。

## 对照与验收

1. 固定起点权重、持出种子、评估终止规则和预算；一次优先改变一个可辨识机制。
2. 同时报告同游戏小时数与同墙钟成本的比较；若硬件或并发负载不同，明确差异。
3. 128 种子跟踪，512 种子正式比较；配对差、区间和多个训练种子优于单点最高分。
4. 正常/无主动/角色及资源扰动分别列组，不能把某一组改善当成全分布鲁棒性。
5. CPU 机制探针、真实游戏正确性、GPU 吞吐和长期效果分别验收。结果未观测到就保留“未验证”。

## 工程与资源

瓶颈由当前测量决定，不预设永远 CPU 瓶颈或永远需要放大网络。优化前拆分引擎、IPC、actor、learner、教师成本；保留完整训练机制做复测。

共享主机不抢占其他任务；完整大实验结束后，将最终/可恢复权重、配置、训练和评估日志及评估结果同步到备用 3090并验证可读。当前状态来自进程和日志，不来自旧 README。
