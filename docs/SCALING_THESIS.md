# 以撒训练的核心思路：算力、数据、可扩展的目标（2026-10-08）

用户与 Claude 在 2026-10-08 的讨论结论，作为之后实验安排的依据。实验本身只记在
[rl/bridge/abplus/EXPERIMENTS.md](../bridge/abplus/EXPERIMENTS.md)，环境和用法在
[rl/bridge/abplus/README.md](../bridge/abplus/README.md)。

## 1. 立场

- 总思路是 Amodei 的 "big blob of compute" 假说（2017）/ Sutton 的 Bitter Lesson：聪明的专用方法长期比不过原始算力、数据量和
  一个可扩展的目标。手写规则、护盾、专才网络都已放弃（2026-10-03 的决定）。
- 手里的证据支持这个方向：一层通关 41.6 → 56.2 → 64.1 → 70.3%（约 1.4 个游戏年，C58 → C64）单调上升；整局 0.84 → 0.95 层
  （3,000 游戏小时）；大网络（C59）在 1,500 游戏小时时没有收益。**参数量不是现阶段的瓶颈**，缺的是信号和算力。
- 数量级：至今总训练量约 2 个游戏年；OpenAI Five 约 45,000 年、AlphaStar 每个智能体约 200 年。离"够"差 2–4 个数量级，
  这不是调参能补的。

## 2. 算力：瓶颈在 CPU

- 每台 16 核跑 16 个引擎约 450× 实时 ≈ 每天 1.2 个游戏年；两台合计约 2.4 年 / 天；GPU 基本空闲（340 万参数）。
- 所以多一倍核数就多一倍数据，投入的优先级是核数而不是显卡；引擎单帧还剩约 20–30% 的优化空间，不再是主项。
- 规则不变：一块 GPU 一个 CUDA 训练器，评估在 CPU 上（`OMP_NUM_THREADS=4`），资源守护每次启动后检查。

## 3. 目标：先把价值的视野拉长，再谈奖励

- 现状：γ = 0.995，每决策 4 帧（0.133 秒），有效视野 1/(1−γ) = 200 个决策 ≈ **27 游戏秒**。两分钟后才兑现的东西（本层的 Boss、
  下一层、资源、道具）在价值头眼里接近零。这解释了：道具的分支标签要靠 60 秒 + 自举才有信号；资源没人捡；换层奖励 3 分
  被折扣得很厉害。
- 第一步（视野实验，C73）：γ → 0.999（视野约 2.7 分钟），同起点同训练量、128 种子对照；若有效再试 0.9995。
- 奖励项（都做成可开关、用对照决定）：现有 出口 3、Boss 2、新房 1、探索 0.5、对怪伤害 1、受伤 0.75/半心、死亡 2、超时 1、
  时间 0.002/决策。补：**回血**（半心单位的正奖励，现在只有"避免扣血"没有"去补血"）、**资源**（硬币 / 炸弹 / 钥匙每个一个小正项，
  真实价值在长视野下自己学）、带血进下一层的加权（换层奖励按剩余血量加权，之后再试）。
- 道具暂停（2026-10-08 用户决定）：分支标签（C68）、实验室练习（C69）、起始构筑（C70）都没有让策略学会用道具；先练无道具
  的通用打法，道具另想办法。

## 4. 数据：多样性比时长更缺

- 一个游戏年里 71% 的决策在一层、只有以撒一个角色、无道具、无诅咒；时长早已超过人类高手（1,000–5,000 小时），分布差得远。
- 便宜的多样性来源（按优先级）：
  1. 属性随机增强（已做，`--stat-aug-prob`，C72）；
  2. **角色随机**（AB+ 15 个角色：属性、起始道具、机制各不同，Azazel 自带 Brimstone、Lost 一击死、Keeper 硬币血）：真实分布，
     不是人造的；C72 之后安排；
  3. 深层优先的起点（`--archive-deep`，C71）、更深的层直接开局（引擎 stage 命令，待验证）、诅咒。

## 5. 回溯搜索（事后教师）的下一步

- 现在只对"受伤"从本房间的恢复点搜 9 个方向 × 几秒（C56 起，是学会躲避的原因）。
- 可扩：死亡比受伤更值得搜（从更早的恢复点、更长的分支，找"本可以活下来"的路线；现在死亡只有 −2）；只对"价值头意外"
  （实际回报远低于预测）的受伤搜，省掉 20–30% 的搜索成本；长视野修好后再试把分支教师用在选门 / 换层时机上。

## 5b. 2026-10-10 的修正：搜索必须被内化，而不是越搜越多（用户的判断，数据证实）

- 事实：`safe_mass_new`（新搜索出的状态上，策略训练前已放在安全方向的概率）在 C64 的一个游戏年里恒为 0.61、整局模式 0.45–0.49；98% 的受伤总能搜到安全方向。搜索每次都能发现策略不会的东西，策略的先验却不涨：
  得到的是越来越强的搜索系统，不是越来越强的策略。原因（我的判断）：只蒸馏恢复点那一个决策（搜索验证的却是持续几步的路线，无记忆的策略执行不出来）、
  备选只有九个手写方向、价值头没有被拉向搜索的发现。C68 的分支教师把发现只喂给价值"选择头"、不改策略，是同一错误的极端形式。
- 教师 v2 的设计：
  - 候选 = **持续性意图 × 每步重算**：意图（九向、原地、放炸弹 / 用道具 / 走向某门）只约束移动、持续 2–8 个决策，射击等每步由策略按分支的新状态重算，意图到期后策略接管；再加策略自身的粘性采样（温度 1，移动方向按几何长度保持）。不用高温采样（以撒的地形里随机抖动很难碰上好解）。
  - 打分 = 折扣回报 + 价值自举，复制分支定噪声底，差值不过噪声底不算发现。
  - **整条分支蒸馏**：最好分支每一步的（状态，动作）都是目标，权重 = 最好 − 实际；价值头回归到分支的 return-to-go。
  - 验收：`safe_mass_new` 和"搜索找不到更好的"比例必须随训练变化；否则这版也算失败。
- 记忆：GRU 隐状态按 worker 延续、只在新一局清零（换房、换层不清）；需要学习器按 worker 时间段做截断 BPTT，排在学习器加速之后。
- 出题—解题（用户引 PAIRED）：单机游戏里出题者选的是状态和种子。题库 = 自然游戏的快照 / 楼层起点；参考解法 = 搜索（教师 v2 的分支）或某场景下的强检查点；
  regret = 参考 − 当前策略；高 regret 的状态做练习起点 + 教师搜索（= Prioritized Level Replay，与 PAIRED 同属 minimax-regret 框架）。便宜代理 = 价值预测误差（训练器免费），
  搜索版 regret 稀疏地校验。警惕：C62 / C71 的手工偏置都输了，regret 选题的合法性要靠对照证明；题库不能被解不了的状态垄断（按排名采样 + 新旧混合）。
- 顺序：教师 v2 → regret 出题（先代理版 C78）→ GRU 记忆（学习器加速之后）；每项先在主机上 3,000 小时对照，再上 HPC 的 10 年尺度。

## 6. 顺序

1. C72 属性增强（第一台）；2. C73 视野 + 回血 / 资源奖励（第二台，C71 之后）；3. 角色随机；4. 算力扩展靠核数（用户研究）；
5. 模型规模等 ≥ 10 个游戏年再看。
