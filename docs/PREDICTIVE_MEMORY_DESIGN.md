# 预测训练的记忆：阶段 1 与阶段 2 设计（2026-11-03）

状态：设计规格，由发起会话（Claude）撰写并负责最终审核；实现由独立会话完成。未实现、未验证。本文只定义要做什么和怎么验收，不替代 `EXPERIMENTS.md` 的实验记录。

## 0. 目的与假设

- 假设 H1：用稠密的多尺度预测损失训练策略的记忆模块（时序 Transformer 的输出 `o_t`），比只靠 PPO 的稀疏奖励，能让记忆保留更多对未来有用的信息，从而提高过层数和减少回头路。
- 假设 H2：让 critic 看到特权信息（actor 看不到的引擎状态），价值估计更准，同小时数下学得更快。actor 不变，部署不受影响。
- 阶段 2 的问题：一个独立的世界模型，在真实数据上对 1 到 256 步后的事件能预测到什么程度。32 步以上不准，则想象训练和潜空间规划不再考虑。

两条假设都必须由 512 种子的同小时数对照判定，不由损失曲线判定。

## 1. 基线与代码基

- 代码基：`abplus-training` 主线（C99 架构：Spatial 192×4，时序 Transformer 256×4、窗口 256、房间槽 128、`--temporal-bptt 256`，obs v2，反事实教师）。不基于 memory-chain v3 或截断分支；那条线仍在验证，不混在一起。
- 起点权重：C99 第二段最终 `segment2-final.pt`（512 种子 1.953 层）。本机与 3090 各有一份。
- 运行配置：`rl/bridge/ops/hpc_c99.sh` 的 COMMON 加 FAST，3 卡布局（学习器 1 卡、actor 2 卡，`--learner-device cuda:1 --learner-process 1 --overlap --decoupled 1`，`--actor-processes 2` 如 B38 步 5），64 workers，minibatch 4096、micro 4096（与 C99 相同；不用 8192，因为这里的对照是 C99 续训）。
- 主机：8×3090 共享主机，Docker 容器，守护规则沿用 memory-chain v3（外部压力、可用内存、自身 OOM、外部 swap 换入），只用空闲 GPU，和 horizon 会话的队列互不抢卡。

## 2. 阶段 1 实验设计

四臂，同起点、同小时数，各续训 10,000 游戏小时（约 12 小时墙钟）：

| 臂 | 预测辅助损失 | 特权 critic |
|---|---|---|
| A0 对照 | 关 | 关 |
| A1 | 开 | 关 |
| A2 | 关 | 开 |
| A3 | 开 | 开 |

判定：每 1,000 次更新 128 种子跟踪；终点 512 种子正式评估（平均过层、到达第 4 层以上数、超时率、往返次数）；同一组持出种子配对比较。另加延迟线索测试（现有 `test_source_horizon` 风格的窗口内版本不适用，用 `rl/bridge/python/tests` 里已有的延迟线索任务）。

主机 GPU 紧张时先跑 A0 与 A3，再补 A1、A2。

## 3. 预测辅助损失（H1）

### 3.1 读出点

从时序输出 `o_t`（256 维，`TokPolicy._heads` 读的那个）接一个预测头 `aux`，输入 `o_t`，不接 `z_t`（要测的是记忆而不是当前帧）。可选消融：输入 `[z_t; o_t]`。

### 3.2 目标与尺度

对每个决策 t 和每个尺度 k ∈ {1, 8, 64, 256}（4 帧/决策，对应 0.13 s、1.1 s、8.5 s、34 s），目标取自同一局内 t+k 的真实 rollout 行，缺失（局结束、超出存储）则掩掉：

- 显式状态目标（回归，按训练集统计标准化）：玩家位置、血量三分量 `phearts`、硬币/炸弹/钥匙、房间内剩余敌人数 `n_ent` 的敌人部分、`room_type`、`stage`。
- 事件目标（二分类，"t 到 t+k 之间是否发生"）：受伤 `hurt>0`、清房 `done==1`、进门/换房（`events` 里的对应位）、拾取（资源增加）、换层、死亡。
- 回报目标：`sum r_{t..t+k}` 的回归。

不预测画面，不预测实体级细节。潜变量目标（`z_{t+k}` 的 stop-gradient 回归）作为可选消融，不在四臂里。

### 3.3 损失

`L_aux = λ · mean_k w_k · (L_reg,k + L_ev,k + L_ret,k)`，λ 默认 0.1，各尺度 `w_k = 1`，各项先按量级归一化（回归用标准化目标的 MSE，事件用 BCE，回报用 Huber）。所有尺度的损失分项都写进 `progress.csv`（`aux_reg_k`、`aux_ev_k`、`aux_ret_k`），它们本身是诊断量：k=64 和 256 的误差是否随训练下降。

`L_aux` 只影响 `aux` 头和它上游的时序 Transformer、Spatial；不经过 PPO 的优势。梯度范围沿用 `--temporal-bptt 256`。

### 3.4 实现要求

- 新开关 `--aux-predict 0|1`、`--aux-horizons 1,8,64,256`、`--aux-coef 0.1`，默认关，关时逐位不变（回归测试）。
- 目标在学习器侧由 rollout 行向前查表得到，跨 rollout 边界的 t+k 掩掉（统计掩掉比例）。
- actor 不变：`aux` 头不进 CUDA 图，推理路径零开销。
- 测试：目标查表正确（人工构造的小序列，含局边界）；掩码正确；关开关逐位等价；一次更新的时间增量 < 5%。

## 4. 特权 critic（H2）

### 4.1 特权信息

桥接已有 `ISAAC_RL_PRIVILEGED=1` 导出 `info`（`abp_bridge.lua` 的 `build_info`）。本阶段取三组，作为单独的 `priv` 行，**不进 actor 的 ROW**：

1. 整层真实布局：13×13 地图的全部房间（含未探索）及房间类型，含隐藏房与超隐位置。
2. 当前房间的隐藏量：敌人总血量与各敌人血量、Boss 血量、未鉴定道具的真实 ID（Blind 下）。
3. 本层剩余可得资源的粗量：未拾取的拾取物数量按类计。

### 4.2 结构

`priv` 经一个小编码器（地图走现有 Map CNN 的同构副本、标量走 MLP）得到 `p_t`（128 维）。价值头改为读 `[zr_t ; p_t]`（局部价值）和 `[yg_t ; p_t]`（全局价值）；策略头、危险头不变。PPO 的优势照常由局部价值算。

### 4.3 实现要求

- 新开关 `--priv-critic 0|1`，默认关，关时逐位不变。
- 桥接侧：特权字段只在 `--priv-critic 1` 时随每个决策导出，走单独的通道/张量；加测试证明 actor 的输入张量在开关前后逐字节相同（可见性审计）。
- `priv` 行在 rollout 里存储，参与 value 重算与 PPO；教师/反事实记录没有 `priv` 时用零向量加一个"缺失"标志位。
- 评测（`eval_tok.py`）不用 critic，所以评测流程不变。

## 5. 阶段 2：离线世界模型评估

### 5.1 数据

- 在四臂训练中打开 `--log-stream`：每个决策写一条记录到按 worker 分片的 zstd 流：Spatial 压缩表示 `z_t`、`g_t`（bf16，共 768 B）、3.2 节的显式状态字段、动作、奖励、事件位、局/层/房间 ID、决策号。每决策约 1 KB；每局抽样 1/4，10,000 小时约 70 GB。写入在学习器侧异步进行，对吞吐影响须 < 3%。
- 另存一份 1/50 抽样的完整 ROW（22.9 KB/决策），供以后换表示时重算。

### 5.2 评估协议

- 模型：因果 Transformer（256 宽 4 层起），输入 `[z_t, g_t, 显式字段, a_t]` 序列，teacher forcing，输出 t+k 的事件概率与显式字段，k ∈ {1, 4, 16, 32, 64, 128, 256}；随机性用离散潜变量（Dreamer v3 式分类潜变量，32×32）作为对照臂。
- 指标：事件 AUC 与 Brier、显式字段标准化 MSE，按 k 画曲线；再按"持出局"和"持出楼层种子"两种切分报告。
- 判定线：k=32 的受伤/清房/换房 AUC < 0.75 或 k=64 的 Brier 不优于只看当前帧的基线，则想象训练与潜空间规划不进入计划。
- 在 3090（host 2）上离线训练，不占用 8 卡主机。
