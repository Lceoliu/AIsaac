## 1. 结论

优先级修订：**先解决写入信用分配与记忆新鲜度，输入扩展后移。** 下一版不先增加 Transformer 层数，也不加入手写寻路、房间价值规则或 RGB 视觉骨干。

首轮的两个硬目标：

1. **让未来任务损失训练过去“选择什么写入”及其源编码过程。** 不是只确认 `room_in.weight` 有梯度，也不是只重新编码离开房间时的最后一帧。
2. **当前策略的训练前向不再混入旧参数生成的 H、决策 KV 或房间摘要。** 从因果原始历史重建当前参数下的记忆；只在每个 PPO epoch 开头刷新一次房间表不够。

两项相互独立：`no_grad` 重算可以使数值变新，却不能恢复写入的信用分配；让 writer 有梯度，也不能使它接收到的旧输入自动变新。必须分别测试、共同验收。它们的代码机制已经确认，实际修复能改善多少游戏表现仍需训练评估。

## 3. 目标数据流

以下是长期组合目标，不是首轮改动包；首轮冻结现有观测 schema，先落地 3.2 / 3.3 的记忆路径：

```text
合法可见的结构化观测 ObsV2
  ├─ 玩家 / 受控实体 / 装备槽 / 充能 / 已知背包 ID 与数量
  ├─ 实体及可见身份、外观状态
  ├─ 地形类型、可见变体与状态
  └─ 已发现地图与门
                 │
         Spatial Transformer（192 × 4）
                 │ z_t, g_t
                 ▼
        concat + projection → 256
                 │
                 ▼
         Temporal Transformer（256 × 4） ◄── 当前参数编码的历史房间观测
                 │                         带观测时间 / 已知状态 / 房间身份
                 │ o_t
                 ▼
     局部 / 全局残差融合 → 策略与价值

H 回到 Spatial：单独做 on/off 对照，不直接宣称应该删除。
决策 KV 的重算 / burn-in：单独检验；去掉 H 不会自动消除旧 KV。
```

### 3.1 输入层：记忆修复完成后，再扩展与压缩

**背包与槽位。** 保存所有已知持有物品的 ID 和数量；装备槽位保留 owner、kind、selected、顺序、身份是否已知，以及合法可见的充能状态。角色身份不再把超过范围的类型压成同一个 ID。多身体和 Drop 操作按现有规格扩展，不写角色专属策略。

背包内部采用通用集合编码，再由可学习查询池化为少量 token；可测试 4/8 个输出 token，但这个数只是计算预算候选，不是“无损压缩”的结论。数量必须参与编码，不能靠重复条目被池化后恰好留下信息。可复用 [Set Transformer](https://arxiv.org/abs/1810.00825) 的集合注意力/学习池化方法，不必重新发明一套物品重要性规则。

**地形。** 将可见 grid type、variant、state 与几何通道结合，而不是继续把行为不同的物体压成同一种占位。第一组输入对照仍保留一个房间 token，以隔离“语义补全”的收益。随后再比较：现有 CNN 的 `4×7` 特征图保留为 **28 个带位置编码的 token**，而不是立刻 flatten 为一个 token。

仅把 R 的 1 个 token 换成 28 个，最大空间序列就从 89 到 116，注意力分数矩阵元素约增加到 **1.70 倍**；这不是总训练耗时增加 70% 的预测。新背包、槽位等还会改变长度，必须实测。

**实体与外观。** 补齐玩家可见的 champion、动画/精灵资源及帧状态等语义；未知道具不能通过其它原始 ID 路径泄漏身份。实体容量根据真实长度分布选择 bucket，超限必须可见，不再静默丢失；不手写“子弹低价值、道具高价值”排序。地形中的楼梯等也不应只能依赖追加到已满实体列表。

这不是只改 PyTorch：需要同步 Lua/C++ bridge、native ROW 编码、Python 编码、rollout buffer、GraphActor buckets 和 checkpoint schema。版本不兼容应明确报错，不能让旧字节布局被新模型误读。RGB 继续只作旁路审计。

### 3.2 目标二：从原始历史重建当前参数下的状态

先做一个小规模、正确性优先的参照路径：固定一条从 episode reset 开始的合法观测 / 动作 / 房间转换历史，在当前参数下按因果顺序重新计算 Spatial、H、决策 KV 和房间写入，之后才计算训练 loss。初版允许慢，不把有偏的捷径当作正确答案。

必须覆盖三个来源：`o_prev`、`ctx_kv`、`o_exit` / pre-chunk room table。刷新表的外层投影但仍输入旧 `o_exit`，只是部分刷新；每个 epoch 重算一次后继续做多个 optimizer step，表也会再次过期。

- rollout 保留原始历史及其因果索引，跨 rollout 的 episode 不能只留下隐藏状态。已有旧数据若没有源历史，不能宣称可精确重建；参照验证使用新采集或完整记录的轨迹。
- 每次 optimizer 更新后，任何依赖参数的缓存都失效；可在同一参数版本的无梯度推理中复用。训练中复用还必须保留正确计算图，不能用 detached 缓存替代需要梯度的历史源。
- actor 参数切换时，按新版本重建所保留历史的状态，或在明确的固定版本边界运行；不能仅改缓存标签或清零记忆冒充重建。actor 与 learner 参数可以有滞后，但各自内部状态必须对应各自使用的参数。
- **PPO 分母保留原采样行为策略的 log-prob**；分子的当前策略条件于同一条原始历史、使用当前参数计算。不能改写 old log-prob 让比率看起来接近 1。
- teacher / CF 分支的原始历史、快照版本和 KV 独立；子分支观察不能回流到父分支。

H 反馈先保留在完整参照中，避免把正确性修复与架构容量削减混为一谈。后续若重放开销过大，再比较去掉 H→Spatial 闭环、保留 Temporal 输出残差等结构优化；这些是性能 / 结构候选，不是“关 H 就已经解决全部旧记忆”。

有限 burn-in 可作为近似优化，但不能作为“已消除旧记忆”的验收证据：多层 KV、H 和房间链可能依赖更早历史。R2D2 的[原论文](https://openreview.net/references/pdf?id=Hy7PKCFCQ)及 [SEED RL 实现](https://github.com/google-research/seed_rl/blob/master/agents/r2d2/learner.py)可作状态漂移 / burn-in 参考；本项目仍须与自己的完整因果重放对齐。

### 3.3 目标一：让未来损失穿过过去的写入选择

仅存离开前最后一帧不够。两条轨迹可能在房间早期看到不同线索，却有完全相同的最后一帧；任何只读最后一帧的函数都无法区分它们。因此首轮数据基础改为：**保留形成房间记忆所需的可见观测序列，而不是只保留旧 `o_exit` 或末帧。**

首先在完整、短轨迹参照中重新执行过去的写入计算并保留计算图，使未来房间的 task loss 能回到早先写入过程和源 Spatial 编码。不能直接复用 actor 原地覆盖状态的实现来冒充可微展开；训练路径需要明确的函数式状态 / 因果 mask。

面向长轨迹的结构候选是“可重算的片段记忆”：

```text
过去片段的原始可见观测（只到当时的写入时间）
    → 当前参数的源编码器
    → 可学习写入 / 压缩器：选择保留哪些信息
    → 少量记忆 token
    → 未来时刻的 Temporal 读取 → 策略 / 价值 loss
                                  │
    源编码器 ← 写入 / 压缩参数 ←──── 梯度
```

这里的写入器只能看写入当时的因果前缀，**不能用未来 query 帮它挑选过去该存什么**；未来损失只负责训练参数。这样训练到的确实是“当时该保留什么”，而不只是“现在如何搜索完整历史”。在线执行与 learner 重算必须是同一个写入函数。

片段压缩可复用学习查询的 attention pooling（如 [Set Transformer](https://arxiv.org/abs/1810.00825) 的思路），并加入时间 / 动作 / 房间身份信息。不能把无序集合等同于有序轨迹；不能只用平均池化宣称保留了所有事件；若写入器本身依赖旧递归隐藏状态，也必须展开该依赖，否则仍然没有绕过旧问题。首版不规定某类道具或房间“重要”，重要性由未来任务损失学习。

原始历史与在线紧凑记忆是两层：前者用于重算与梯度，后者用于决策。重复进房可更新当前事实索引，但不能覆盖掉早先训练时间点的原始版本或删掉唯一线索。房间键只标识已观察到的房间，时间 / 已知 mask 显式记录；不从引擎更新未重访房间，也不泄漏未探索拓扑。

这条路径能对保留片段的编码与写入建立直接信用分配，不要求对整个游戏模拟器求导，也不自动解决过去动作如何导致观察到线索的探索问题。更不能恢复未记录或已淘汰的数据。容量截断、片段长度和版本内存成本必须公开测量；在 64 GiB 容器限制下，先完成短轨迹参照，再优化重算 / 存储，不能先静默截断再宣称两个问题都解决。

### 3.4 首轮验收：两项缺一不可

**G1，写入学习：** 构造线索只在早期出现、后续观察完全相同、跨房间 / 跨训练 chunk 才产生任务损失的测试。梯度必须到达早期源编码器和写入选择参数，而不仅是读取头或最后的 `room_in`；再训练这个延迟线索任务，持出准确率应显著高于机会水平，遮掉早期线索后优势消失。非零梯度只是必要检查，不等于学会。

**G2，状态新鲜度：** 固定同一历史与参数，learner 重算、actor 因果逐步执行和缓存优化路径的 H / KV / 房间记忆及最终输出在选定 dtype 的数值容差内一致；执行一次参数更新后再次比较。不能只测首次更新前。故意向旧缓存注入扰动时，新的当前策略前向必须不受影响，因为不应读取该缓存。

补充：截断未来观测前后，时刻 t 的结果一致；跨 rollout、房间重访、episode reset 和 CF 分叉都覆盖。两项通过后才做实际训练速度和游戏评估。

## 4. 实施与实验顺序

| 阶段 | 只改变什么 | 用什么决定下一步 |
|---|---|---|
| M0 | 冻结输入、主干规模、动作空间；保存完整因果原始历史，建立诊断 | 复现旧源梯度断点与参数更新后的缓存差异 |
| M1 | 小轨迹完整重算参照：当前参数生成 H、KV、房间状态 | G2 首次更新前与更新后都通过 |
| M2 | 写入及源编码保留梯度；检验跨房间延迟线索 | G1 梯度和实际学习同时通过，G2 仍通过 |
| M3 | 可重算片段记忆、重算 / 存储优化，必要时再比较 H 拓扑 | 不破坏 G1 / G2 的前提下实测 CPU、GPU、RAM 和吞吐 |
| M4 | 先分离 fresh-state / 写入梯度的消融，再测试组合；运行游戏对照 | 两种开局的层数、超时、跨房间行为及效率 |
| A1 / A2 | 记忆验收后再做 ObsV2 和 1 / 28 地形 token | 输入补全与空间容量的独立收益 |

这是顺序，不要求把每个候选都变成长实验。首轮不增加物品 / 地形 / 动作空间改动；先用短轨迹证明两个记忆目标，再优化到可训练规模。已有输入缺失继续记录，但不再抢占本轮优先级。

### 开局分布与比较口径

- 接受此前讨论的 **50% 有 D6 / 50% 无 D6** 作为训练分布候选；同组结构对照必须使用相同开局分布。不能只让新模型接受 no-D6 训练，再把提升全部归因于架构。
- 第一轮固定其它角色 / 环境差异，避免同时改变角色覆盖、操作空间、观测和课程。
- C99 最优权重仍作冻结参照；兼容层可 warm-start，但新增 token、H 通路变化或动作维度变化不是严格等价迁移。新 token 即使初始化为零也可能改变 attention softmax，不能承诺初始输出不变。
- 128 seeds 用于跟踪；正式候选分别报告 D6 / no-D6 的 512-seed 结果，使用相同持出种子配对比较并给出置信区间。单个训练 seed 不能证明收益可重复，入选方案再做多训练 seed 复验。

### 观测指标与通过条件

主指标：平均层数、超时率、达到各层的比例；D6 / no-D6 分开。辅助记录反复 A→B→A 访问及每游戏小时发生率，但不把所有回头路都判为错误。区分第一房间战斗失败、可见机关交互失败、跨房间后的导航失败，才能判断记忆改动是否打中了问题。

正确性必须全部通过：

- Python / native 编码在同一合法观测上匹配；Blind / 未鉴定身份变化不能改变不该暴露的输入。
- 已确认丢失的可见语义可以区分；数量、槽位、充能边界有具体输入对照。
- 时刻 t 的记忆不含 t 之后的观测；CF 子分支不影响父分支。
- G1 和 G2 都通过；仅 MemoryEncoder 非零梯度或同参数首次前向一致都不能替代完整验收。
- episode / floor / room 重置与重访行为正确，actor / learner 在同参数同历史下对齐。

收益门槛：完整评估中 no-D6 平均层数的配对差值置信区间下界大于 0，超时率确实降低；D6 表现和吞吐同时列出，不用单一综合分掩盖退步。若差值不确定，则结论是未分出胜负，而不是“架构成功”。出现 D6 回退时单独讨论取舍，不事后调整验收口径。

性能记录包含 bridge / IPC / CPU 编码、actor、learner、RAM / VRAM 峰值。结构变化后的 ETA 用新实测速度估算，不沿用旧模型约 736× 的短测均值。
