# 宏观层离线工具：AB+ / 忏悔+ 楼层生成器、隐藏房推断、道具先验、规则规划器（2026-09-27）

对应 [MACRO_PLANNING.md](../docs/MACRO_PLANNING.md) 的 P0。全部离线运行，不启动游戏。

**核心**：把 Afterbirth+ v1.06（Linux x64，带函数名）的楼层生成代码逐函数翻译成 Python。
- 给定种子，得到与引擎相同的楼层：网格、房间形状、房间类型和布局、Boss、诅咒，以及每个房间的三个种子。
- 与引擎逐种子、逐房间一致：9,774 个地下室种子的引擎日志，以及 6,000 个引擎整层导出（第 1–8、10、11 层）。范围和局限见下文"验证"。
- 有了它，就能离线生成任意多的楼层当训练数据，也能在已知生成规则下精确推断隐藏房。

**信息边界**（PROJECT_SPEC §3）
- 种子和生成器只用于离线造数据和评估。
- 送给策略的输入只能是玩家看得见的地图，例如 `Floor.visible()` 或规划器里的 `explored_map()`。

**数据来源**
- 房间库只需要 AB+ 的 `afterbirthp.a`。
  - 这一个档案就包含 `stages.xml` 和第 0–24 号楼层的全部房间文件，并且在引擎里会覆盖 `rooms.a`、`afterbirth.a` 中的同名文件。已逐房间核对：只用它和三个档案叠加的结果相同。
  - 默认路径是 `analysis/abplus-linux/resources/packed/afterbirthp.a`，可以用环境变量 `ISAAC_ABPLUS_AFTERBIRTHP` 改。
- 道具品质来自 `analysis/resources/repentance-a/config/items.xml`（忏悔+）。

## 用法

```python
from isaac_macro.roomconfig import default_room_config
from isaac_macro.level import GameContext, generate_floor
from isaac_macro.run import generate_run
from isaac_macro.floor import Floor
from isaac_macro.secret import secret_posterior

rc = default_room_config()
level = generate_floor(rc, GameContext(), stage=1, stage_type=0, stage_seed=2334308359)
floor = Floor.from_level(level)
print(floor.ascii())                       # S 起点，B Boss，T 宝箱房，$ 商店，s 隐藏房，X 超级隐藏房
run = generate_run(rc, 'SXG6 R8XA', last_stage=8)   # 游戏里显示的种子字符串，或数字种子
post = secret_posterior(floor.visible())   # {格子: 概率}，只用玩家可见的信息
```

- `GameContext` 描述生成时要读的游戏状态：
  - 成就（默认全部解锁）、难度；
  - 玩家的心、钥匙、硬币、饰品、道具；
  - 本局的状态标志（跨层累积，例如已出现过的 Boss 和七宗罪）。
- `debug_start=True`：复现本项目引擎实例的开局方式。实例用 `--set-stage=1 --set-stage-type=0` 启动，走的是 `Game::StartDebug`，所以第一层固定是地下室 I（类型 0），并视为全部解锁。
  - 这也解释了之前 Boss 池探针的疑问："300 局的地下室类型全是 0"。
  - 正常开局走 `Game::Start` → `SetNextStage`，第一层可能是地窖或燃烧地下室。

**网页：以撒小测试 · 找隐藏房**（`web/`）

一个隐藏房测验站：用种子生成真实楼层，在游戏自己的小地图上用炸弹（忏悔+ 还有红钥匙）找出隐藏房，按炸得准不准计分、排名。一层结束后可以看 AI 是怎么找的。

- **首页**：做成游戏主菜单的样子，素材都是游戏自己菜单里的（`roomart.py` 的 `MENU_ART`）：带草图的墙（`EmptyScreen`）和暗角（`MenuOverlay`）、`GameMenu` 钉着的纸（玩法菜单，左边是它的光标）、`LeaderboardMenu` 的纸（排行榜）、`ui_FortunePaper` 的纸板条（计分规则）、`ui_streak` 的道具名黑条（副标题）、`Menu_DailyRun` 的草图便签（按它 `Idle` 动画里 `SketchPaper` 和 `Sketch` 第 0 帧的位置合成：粉色便签上的以撒）和主菜单的苍蝇。纸和纸板用 9 宫格拉伸，撕边不变形；道具名黑条的两端保持原宽、只拉伸中段，并按两倍高度画，文字只落在笔刷实心的部分（切口选在笔刷上下边缘平直的列，不旋转，避免切片之间出现细缝）。标题"以撒小测试"旁边是以撒竖大拇指。
  - 玩家名（存在浏览器里，附一个随机的玩家 id）、游戏版本、三种玩法、计分规则和排行榜。页面一打开就在后台准备运行环境，并逐个解析房间文件，点"开始"时通常已经就绪。
  - **今日挑战**：种子由日期（北京时间）和游戏版本算出（FNV-1a），所有人同一局，7 层。
  - **随机挑战**：随机种子，7 层，计入总榜。
  - 跨零点：今日挑战的日期在开局时定下，写进网址（`day`）。做到一半过了零点，剩下的层仍算在开局那天的榜上（原来按提交时的日期算，会记到新的一天），标签显示"9 月 27 日挑战"并提示一次；零点后刷新也回到同一局（昨天的挑战还能接着交，数据库只收今天和昨天的今日挑战成绩），更早的网址换成当天的挑战。
  - 待补交的成绩：数据库拒收的（返回 SQLSTATE，比如过了提交期限）从队列里去掉，不再挡住后面的成绩；断网、网关错误照旧留着下次补交（`tests/js/check_scoreboard.mjs`）。
  - **自由练习**：原来的工具，自选种子和开局选项，随时看完整地图，不计分。
  - 挑战里：没有"显示概率"和"提示下一步"，"完整地图"要等这一层找完或放弃才能看（它会直接显示答案）；每层的进度存在浏览器里，刷新不会重来；没有撤销，只能"放弃这一层"（按已找到的计分并揭晓）；运行只生成挑战的 7 层（`run` 的 `floors` 参数；原来是 5 层，2026-09-27 改成 7 层让分数拉得开。同一天的今日挑战种子不变，前 5 层和原来一样，已有的进度接着算）。提示和完整地图在自由练习里照常可用。
- **计分**（`js/score.js`）：隐藏房 +100，超级隐藏房 +150，究极隐藏房 +200；炸弹或红钥匙什么都没找到 −25；一次不空、全部找到 +50。每层不低于 0 分。
- **AI 怎么找**（`js/ai.js`）：一层结束后（找完或放弃），结果卡给出"AI 平均要消耗几颗炸弹、几次红钥匙"，点"看 AI 怎么找"在地图上一步步回放：AI 每一步看到的概率、它的选择（框出来）和结果，之前的步骤标上序号，可以单步、自动播放。
  - AI 只知道玩家知道的：看得见的地图、房间布局和门位，以及这一层有哪几种隐藏房（把联合后验限制到这些种类）。它先用炸弹，每次炸隐藏房或超级隐藏房概率最高、又挨着已知房间的墙；两者都找到后（忏悔+）用红钥匙，每次开最可能通到究极隐藏房的门位，没有门位直接挨着候选时，挑两格内候选最多的。
  - "平均"是在联合后验上精确求的期望：每一步按它会揭示的结果把假设分组，递归到底。在 400 局胎衣† 和 400 局忏悔+ 楼层上：AI 每层都能找全（没有卡住的假设），平均约 2.8 颗炸弹，忏悔+ 另加约 1.3 次红钥匙；实际回放的平均和期望一致。
  - 顺带修正了一条规则：炸过、什么都没有的墙仍然是门位，红钥匙可以在那里开红房间（原来会被排除，导致有的楼层找不到究极隐藏房）。撤销时恢复被覆盖的标记。
- **排行榜**（`js/scoreboard.js`）：分"今日"（今日挑战）和"总榜"（所有挑战），按游戏版本分开。每位玩家、每个游戏、每个种子、每层只记第一次的成绩。
  - 共享排行用 Supabase：在项目的 SQL Editor 里运行一次 [`web/scoreboard.sql`](web/scoreboard.sql)（建表、只许读和新增的权限、两个排行视图），再把项目 URL 和 publishable key（`sb_publishable_...`，旧项目是 anon key）写进 `rl/runs/macro/supabase.json`（`{"url": ..., "key": ...}`，不进 git）。`build_site.py` 和本地服务都会读它。没有这个文件时，成绩只存在当前浏览器里，页面会说明这一点。publishable key 只放在 `apikey` 头里（它不是 JWT）。
  - 已接入的项目：`evvufjkrmxdjootmgeyk`（2026-09-27）。核对过：两个视图可读；新增一条越界的分数会被表上的检查拒绝（说明写入权限和检查都生效，没有留下测试数据）。
  - 分数由浏览器计算和提交，懂行的人可以伪造；表上的检查只把分数限制在一层能拿到的范围内。提交失败会先存在本机，下次联网时补交。
- **手机**（2026-09-28 在 375×812 和 360×640 上走过首页、自由练习、挑战和 AI 回放）：页面在 980px 以下是单栏，面板在地图下方，所以点房间直接弹出布局对话框（`minimap.js` 的 `openRoom`），不用往下翻；AI 回放的数字和按钮排在说明前面，进入回放时把地图滚到顶部，地图和按钮在一屏里；走一步只滚动步骤列表，不滚动页面（原来 `scrollIntoView` 会把整页带走）。首页的加载提示原来用了 `busy` 类，和棋盘上"生成中"角标的样式撞了，首次打开时会浮在标题上，现在叫 `working`；首页隐藏的站名不再占位，右上角的按钮回到第一行。
- **地图**：房间图标的帧（13×12）比房间格子（9×8）大，原来图标也接收鼠标，所以隐藏房的悬停范围会超出它的格子；现在图标和格子贴图都不接收鼠标，由房间自己的格子（透明矩形）接收。窄房间：游戏的小地图贴图本来就是细长条，但特殊房间的图标会把它整个盖住，现在窄房间的图标画成一半大，细长条露在外面；"文字标签"模式下窄房间画成走廊。
- **反馈**：找到隐藏房时播放游戏里的发现隐藏房音乐（`music.xml` 第 85 首，`GridEntity_Door::TryBlowOpen` 0x2FC530 在炸开没去过的隐藏房时播放），以撒竖大拇指（玩家动画 `Happy`）并弹出得分；一层找完时加上游戏的竖大拇指音效（`sounds.xml` 268）。右上角可以静音，会记住。标题旁边的以撒也是这个动画的一帧。
- **速度**：
  - 生成器不再用 numpy（`isaac_macro/f32.py` 用 `struct` 做 float32 舍入；对 300 局双版本整局逐字段比对，结果和 numpy 版完全相同），浏览器少下载约 3 MB、少一步初始化。
  - 运行环境、生成器代码和房间数据并行下载；房间文件在空闲时逐个解析（`warmup`），之后生成一局挑战（7 层）在浏览器里约 0.06–0.15 秒（忏悔+ 约 0.12–0.33 秒，2026-09-27 在本机 Pyodide 上测）。
  - 每层画好后，一次请求取回这一层所有能看的房间布局（`layouts`），再预先加载它们的贴图，所以点房间或鼠标停在房间上时直接出原版画面；还没加载好时显示同样大小的占位，不再先闪出示意图。拼好的房间按门的状态缓存。

- **两种运行方式，页面代码相同**：
  - 本地：`python rl/macro/web/server.py --port 8792`（或 `.claude/launch.json` 的 `abplus-mapgen`），打开 http://127.0.0.1:8792/ 。服务端直接读本机两个游戏的档案（只读）。
  - 静态站点（GitHub Pages）：`python tools/build_site.py [--out 目录]`，默认输出到 `rl/runs/macro/site`（不进 git）。生成器在浏览器里用 Pyodide 运行（v314.0.7，Python 3.14，从 jsDelivr 加载）：页面起一个模块 Web Worker，加载 `py/macro.zip`（`isaac_macro` 和 `web/api.py`）和 `data/<game>.zip`，再调用和本地服务同一套 `api.call()`。本地预览用 `.claude/launch.json` 的 `isaac-site`（端口 8793）。
- **后端结构**：`web/api.py` 是全部逻辑（生成、联合后验、布局、小地图贴图）；`web/server.py` 只是 HTTP 外壳。静态站点的游戏数据是从档案里导出的文件（`archive.FileSet` 读取，路径小写），`tests/test_web.py` 核对两条路径生成的结果逐字段相同。
- **找隐藏房**（默认视图）：
  - 地图只画玩家已探索的房间（忏悔+ 外扩 2 格，留出究极隐藏房的候选位置）。
  - 选工具后点墙外的格子。炸弹要挨着已知房间；红钥匙要在已知房间的布局门位外（找到的隐藏房和红房间四面都算）。结果照生成的答案揭晓：炸开是空的就打个叉，找到就弹出对应的房间，红房间会连通四邻的隐藏房（`Level::MakeRedRoomDoor`，RVA 0x34D010，静态阅读，没在游戏里核对）。
  - 每一步都在浏览器里按联合后验条件化（`js/infer.js`：删掉不相容的假设再归一化）。"显示概率"和"提示下一步"默认关闭，打开后概率格和建议随之更新；两个开关旁的"?"说明它们只按生成规则推算、不读取真实位置。鼠标停在格子上显示概率和"假如是某种隐藏房，另外两种多半在哪"。
  - 点房间（或鼠标停在房间上）看它的布局：障碍物、刷怪点和门位。门只画通向玩家已知房间（探索过的、找到的、红房间）的那些，其余门位就是墙，和游戏里一样，不会从门泄露隐藏房的位置（`room.slot_targets` 给出每个门位通向的格子）。选红钥匙时，红钥匙能打开的门位画成红色虚线门（和小地图上红钥匙能点的格子是同一批）；选炸弹时不画。
  - 练习里可以撤销、重来、揭晓答案。全部找到后，给出本层得分、所用炸弹数和"照着提示炸"的期望炸弹数（按同样的建议策略在联合后验上精确求期望）。
- **完整地图**：所有房间（要找到才显示的画成"没到过"的暗格），点房间看布局、门位和刷怪点。
- **房间布局用原版贴图**（`web/roomart.py` 打包，`js/roomart.js` 拼画）。两个游戏都用忏悔+ 的美术（`graphics.a`、`afterbirth.a`、`afterbirthp.a`、`repentance.a`，只读），胎衣† 借用它；背景、网格物体和实体的编号两边相同。

**与引擎逐种子一致**〔事实〕

  - 诅咒；

## 结果

除特别注明外，以下都在第 1–8 层上统计。
- **生成楼层**：楼层类型和诅咒按整局规则产生；隐藏房、超级隐藏房的真实位置来自生成器本身。
- **引擎楼层**：上面探针读出的 5,200 层（第 1–8 层）。生成器已被证明与引擎逐房间一致，两者本应给出相同的统计。

**隐藏房推断**（`tools/eval_secret.py`；引擎楼层 5,200 层，第 1–8 层）

| 方法 | 第 1 颗命中 | 2 颗内 | 3 颗内 | 平均用弹 |
|---|---:|---:|---:|---:|
| 隐藏房：邻居最多的格子先炸（常见玩法） | 30.4% | 54.7% | 72.6% | 2.82 |
| 隐藏房：先炸"布局有门位却没有门"的墙（玩家经验） | 63.9% | 81.8% | 89.5% | 1.88 |
| 隐藏房：放置规则的精确后验（不看普通房间布局） | 43.0% | 69.8% | 85.5% | 2.16 |
| 隐藏房：**放置规则 + 布局证据** | **88.6%** | **95.6%** | **98.0%** | **1.20** |
| 超级隐藏房：深度先验 | 59.5% | 79.3% | 90.0% | 1.81 |
| 超级隐藏房：**深度先验 + 布局证据** | **76.7%** | **90.0%** | **95.0%** | **1.42** |

在另一批 7,928 个生成楼层上结果一致（`tools/eval_secret.py 1000 2`）：隐藏房 88.9% / 96.6% / 98.7% / 1.17，超级隐藏房 77.6% / 91.0% / 95.9% / 1.39。

- **布局证据**（`LayoutEvidence`、`hidden_posterior`）
  - **来源**：普通房间的布局是在两个隐藏房都放好之后才选的。选布局时要求包含通往隐藏房的门位，并且强烈优先门位恰好等于要求的布局（系数 9.99）。
  - **推论**：某个布局在一面墙上有门位、这面墙外却没有可见的门，要么是一次概率很低的"非精确"抽取，要么墙后就是隐藏房或超级隐藏房。反过来，布局在某面墙上没有门位，就能直接排除墙后的格子。
  - **计算**：按房间库权重精确算出每个房间布局的似然比，与放置规则一起求隐藏房和超级隐藏房位置的联合后验。
  - **与玩家经验的关系**：玩家常说的"对称房间两三面有门、一面是墙时，隐藏房多半在墙后"，就是这条规则的定性版本。
  - **非精确抽取的下限**（09-27）：模型用房间库的初始权重，没有模拟同一层里"选过的布局权重衰减"。
    - 当门位完全吻合的布局权重占比 ×9.99 ≥ 1 时，按初始权重引擎必选吻合的布局，模型会把门位更多的布局判成不可能。
    - 但前面的房间用掉吻合的布局、权重衰减之后，引擎偶尔也会选到门位更多的布局。实测约每 3,000 个这样的房间出现 1 次（AB+ 1/2,629，J460 移植 1/3,176；其他情况下模型预测的比例与实测吻合）。
    - 一旦出现，真实的隐藏房组合就会被判成不可能。现在这条分支至少保留 5×10⁻⁴ 的概率（`secret.NON_EXACT_FLOOR`）。
    - 上表是加了下限之后的结果：引擎楼层上隐藏房第 1 颗命中从 88.0% 升到 88.6%，超级隐藏房从 76.3% 升到 76.7%。
- **前提**：要能认出房间布局，才知道每面墙有没有门位。AB+ 的 13,064 个普通布局里，没有两个布局内容相同而门位不同，所以只要把房间里的障碍物和敌人与房间文件比对，门位就是确定的。桥接还没做这个识别；做之前只能用"放置规则"那一行（平均 2.2 颗）。
- **校准**：预测概率与实际命中频率吻合，例如引擎楼层上 0.856 对 0.857、0.986 对 0.991。
- **只有特殊房间的布局影响放置规则**：黑名单只统计在隐藏房之前放下的房间，即 Boss 房、超级隐藏房和其他特殊房间。普通房间的布局只以"证据"的形式起作用。
- **超级隐藏房的规律**
  - 它总是除 Boss 房外最深的死路，只挨着 1 个普通房间（100%）。
  - 按"深度不小于所有可见死路"筛出的候选平均 5.4 格，真值 100% 在候选中。
  - 先验按两个特征拟合（`tools/fit_super_secret.py`，11,896 层）：相对最深可见死路的深度差，以及相对 Boss 房的深度差（Boss 房先挑最深的死路，比它更深的候选权重只有 0.19）。

**整局一致性检查**（`tools/check_rep_runs.py 400 11 11`）
- 400 个种子 × 两种开局，共 7,924 层（第 1–8、10、11 层），每层约 6.6 ms。
- 没有任何错误，也没有违反这些不变量：每层都有 Boss 房、隐藏房和超级隐藏房，房间不重叠，所有房间都连通。
- 各类房间的出现频率合理：
  - 子宫及以后没有商店和宝箱房；
  - 默认 0 硬币、0 钥匙时没有赌博房和宝库；
  - 星象房约 1%（之前的宝箱房都进过时的基础概率）；
  - 每层都有究极隐藏房。
- 诅咒抽取在 20 万个种子上核对：出诅咒的概率 10.04%，六种各约 1.67%，与规则一致。
- **一个如实复现的引擎怪行为**：七宗罪小头目都出现过之后，小头目段会沿用诅咒房的死路（反编译中的 `local_e8`）。
  - 结果是诅咒房被重复放置，或被普通房间覆盖。
  - 这种情况很罕见，要在游戏里确认。

**隐藏房推断**（`rep/secret.py`；`tools/eval_secret.py 1000 2 --rep`，移植生成的 7,928 层，第 1–8 层）

隐藏房和超级隐藏房的放置规则与 AB+ 相同，只多了"封格"：
- 放好（最后一个）Boss 房后，J460 会封掉它的格子和四邻（VA 0x739A0D）；深牢 II（或迷宫诅咒下的深牢 I）在生成网格时还会封掉起始房间上方的 (6, 5)。隐藏房不会放在被封的格子上。
- 黑名单本来就覆盖了 Boss 房的每一面，所以封格只多排除了 L 形 Boss 房缺角那一格和 (6, 5)。影响很小，但不建模会把真值判成不可能：加非精确下限之前，7,928 层里有 5 层是这样。

新东西是**究极隐藏房**（`GetNewUltraSecretRoom` 0x5AE640，在隐藏房之后放）：
- 它不挨着任何房间或被封的格子。候选格的评分方法和隐藏房一样（Random(5)+10，距离 2 以内有 1、2 个房间时减 6、3）。
- 放好后，距离 2 以内的房间会在朝向它周围空格的每一面加一个门位，也就是红钥匙能开出红房间的位置。普通房间随后才选布局，这些门位也是必需门位。
- 所以一面有门位却没有门的墙，墙后可能是隐藏房、超级隐藏房，也可能是究极隐藏房旁边的红房间空格，三者要放在一起推断。
- 核对：模型推出的普通房间必需门位与生成器的门位逐房间相同（488/488）。约 13% 的普通房间带有红房间门位。

**两条玩家经验的量化**（同一批 7,928 层；`eval_secret.py --rep` 末尾会打印）
- **"红隐大多生成在四周有好几个房间的地方"**：真实红隐距离 2 以内有 ≥2 个房间格的占 92.5%（≥3 的占 45.7%），而所有合法格子里只有 29.8%。这是放置规则的直接结果：候选格按距离 2 以内被占的格子数打分，只有 1 格的减 6、2 格的减 3，3 格以上不减。
- **"红隐概率高了，隐藏房的后验会下降，甚至排除某些候选"**：红隐离隐藏房、超级隐藏房的曼哈顿距离都至少 3。挨着它或只隔一格的格子都会落选，因为这两种房间每一面的门位目标都在红隐的黑名单里。红隐还会给附近房间加红房间门位。
  - 和不管红隐的 AB+ 模型相比，485 层（6.1%）里有原本 ≥10% 的隐藏房候选被压到 1% 以下，一次也没有压错。
  - 1,248 层里有候选的概率减半，其中 93 次减半的正好是真正的隐藏房。
- 反过来也成立：找到隐藏房后，红隐第一猜从 74.5% 升到 77.5%；知道红隐位置时，隐藏房第 1 颗命中从 88.4% 升到 91.7%。
- 超级隐藏房先验在忏悔+ 楼层上重新拟合（`tools/fit_super_secret.py 1500 1 --rep`，11,896 层）。放置方法相同，权重与 AB+ 的差别在噪声以内。
- 这些数字相对于未经验证的移植；与游戏核对后才能当成游戏里的命中率。
