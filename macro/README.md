# 宏观层离线工具

更新：2026-10-21。本目录保留楼层生成、隐藏房推断、道具先验和规则规划工具，供离线分析、机制核查和对照使用。**不是当前在线策略的手写高层控制器。** 早期“规则管宏观、网络只打架”的方案已被一个策略覆盖整局的主线取代。

**数据来源**
- 房间库只需要 AB+ 的 `afterbirthp.a`。
  - 这一个档案就包含 `stages.xml` 和第 0–24 号楼层的全部房间文件，并且在引擎里会覆盖 `rooms.a`、`afterbirth.a` 中的同名文件。已逐房间核对：只用它和三个档案叠加的结果相同。
  - 默认路径是 `analysis/abplus-linux/resources/packed/afterbirthp.a`，可以用环境变量 `ISAAC_ABPLUS_AFTERBIRTHP` 改。
- 道具品质来自 `analysis/resources/repentance-a/config/items.xml`（忏悔+）。

## 用法

```python
from isaac_macro.roomconfig import default_room_config
from isaac_macro.level import GameContext, generate_floor
from isaac_macro.run import generate_run
from isaac_macro.floor import Floor
from isaac_macro.secret import secret_posterior

rc = default_room_config()
level = generate_floor(rc, GameContext(), stage=1, stage_type=0, stage_seed=2334308359)
floor = Floor.from_level(level)
print(floor.ascii())                       # S 起点，B Boss，T 宝箱房，$ 商店，s 隐藏房，X 超级隐藏房
run = generate_run(rc, 'SXG6 R8XA', last_stage=8)   # 游戏里显示的种子字符串，或数字种子
post = secret_posterior(floor.visible())   # {格子: 概率}，只用玩家可见的信息
```

- `GameContext` 描述生成时要读的游戏状态：
  - 成就（默认全部解锁）、难度；
  - 玩家的心、钥匙、硬币、饰品、道具；
  - 本局的状态标志（跨层累积，例如已出现过的 Boss 和七宗罪）。
- `debug_start=True`：复现本项目引擎实例的开局方式。实例用 `--set-stage=1 --set-stage-type=0` 启动，走的是 `Game::StartDebug`，所以第一层固定是地下室 I（类型 0），并视为全部解锁。
  - 这也解释了之前 Boss 池探针的疑问："300 局的地下室类型全是 0"。
  - 正常开局走 `Game::Start` → `SetNextStage`，第一层可能是地窖或燃烧地下室。

**网页：以撒小测试 · 找隐藏房**（`web/`）

一个隐藏房测验站：用种子生成真实楼层，在游戏自己的小地图上用炸弹（忏悔+ 还有红钥匙）找出隐藏房，按炸得准不准计分、排名。一层结束后可以看 AI 是怎么找的。

- **首页**：做成游戏主菜单的样子，素材都是游戏自己菜单里的（`roomart.py` 的 `MENU_ART`）：带草图的墙（`EmptyScreen`）和暗角（`MenuOverlay`）、`GameMenu` 钉着的纸（玩法菜单，左边是它的光标）、`LeaderboardMenu` 的纸（排行榜）、`ui_FortunePaper` 的纸板条（计分规则）、`ui_streak` 的道具名黑条（副标题）、`Menu_DailyRun` 的草图便签（按它 `Idle` 动画里 `SketchPaper` 和 `Sketch` 第 0 帧的位置合成：粉色便签上的以撒）和主菜单的苍蝇。纸和纸板用 9 宫格拉伸，撕边不变形；道具名黑条的两端保持原宽、只拉伸中段，并按两倍高度画，文字只落在笔刷实心的部分（切口选在笔刷上下边缘平直的列，不旋转，避免切片之间出现细缝）。标题"以撒小测试"旁边是以撒竖大拇指。
  - 玩家名（存在浏览器里，附一个随机的玩家 id）、游戏版本、三种玩法、计分规则和排行榜。页面一打开就在后台准备运行环境，并逐个解析房间文件，点"开始"时通常已经就绪。
  - **今日挑战**：种子由日期（北京时间）和游戏版本算出（FNV-1a），所有人同一局，7 层。
  - **随机挑战**：随机种子，7 层，计入总榜。
  - 跨零点：今日挑战的日期在开局时定下，写进网址（`day`）。做到一半过了零点，剩下的层仍算在开局那天的榜上（原来按提交时的日期算，会记到新的一天），标签显示"9 月 27 日挑战"并提示一次；零点后刷新也回到同一局（昨天的挑战还能接着交，数据库只收今天和昨天的今日挑战成绩），更早的网址换成当天的挑战。
  - 排行榜有"今日""昨日""总榜"三个标签；"昨日"是北京时间昨天那一期今日挑战的榜。
  - 待补交的成绩：数据库拒收的（返回 SQLSTATE，比如过了提交期限）从队列里去掉，不再挡住后面的成绩；断网、网关错误照旧留着下次补交（`tests/js/check_scoreboard.mjs`）。
  - **自由练习**：原来的工具，自选种子和开局选项，随时看完整地图，不计分。
  - 挑战里：没有"显示概率"和"提示下一步"，"完整地图"要等这一层找完或放弃才能看（它会直接显示答案）；每层的进度存在浏览器里，刷新不会重来；没有撤销，只能"放弃这一层"（按已找到的计分并揭晓）；运行只生成挑战的 7 层（`run` 的 `floors` 参数；原来是 5 层，2026-09-27 改成 7 层让分数拉得开。同一天的今日挑战种子不变，前 5 层和原来一样，已有的进度接着算）。提示和完整地图在自由练习里照常可用。
- **计分**（`js/score.js`）：按一局开始的那天（北京时间）选规则，一局从头到尾用同一套，同一天的榜也不会混着两套。每层不低于 0 分。
  - v1（到 2026-09-28）：隐藏房 +100，超级隐藏房 +150，究极隐藏房 +200；炸弹或红钥匙什么都没找到 −25；一次不空、全部找到 +50。
  - v2（从 2026-09-29 起，按站长的设计）：房间分第 1、2 层减半，第 3–7 层不变；每个隐藏房一次就找到（和上一次发现之间没有空炸）第 1–5 层 +25、第 6、7 层 +50；单连隐藏房（只挨着一个已知房间）+25，单连究极隐藏房（只有一个门位能开红房间连到它）+50；一层不空第 1–2 / 3–5 / 6–7 层 +25 / +50 / +125；空炸仍是 −25。一层最多 800 分。"单连"要找到以后才显示，满分也不算它，免得提前透露位置。依据：在 7,000 层挑战楼层上，单连隐藏房占 1.6%，AI 平均要 3.9 次（普通 1.6 次）；单连究极隐藏房占忏悔+ 楼层的 6.4%，AI 要 5.4 次（普通 3.8 次）；各层对 AI 的难度差不多（胎衣† 第 1–7 层平均 2.4–2.75 颗炸弹），超大层只多 5%，所以没有加分。
  - 随机挑战的规则版本记在本机的这一局记录里（`hr-run-v1:` 的 `rules`），过了零点接着玩也不变；首页的计分条按当天显示对应的一套。
  - 一层不空：地图上盖下忏悔+ 饰品"满分考卷"（Perfection，items.xml 饰品 145，俗称 A+）的图标，结果卡上也有它（`fx.js` 的 `stampPerfect`）。
  - 数据库每层上限从 500 改成 1000（`web/scoreboard.sql` 里有给旧表的 `alter table`）。`art.json` 每次打开都向服务器确认（没变时是 304），免得更新后还用着缓存的旧素材表。
  - 红钥匙留给红房间和究极隐藏房：直接用在隐藏房或超级隐藏房上时（那面墙用炸弹也能炸开），按一颗炸弹算，工具自动换回炸弹（`play.js` 的 `useKey`，2026-09-28 按用户要求；只剩究极隐藏房时留在红钥匙）。红钥匙开出的红房间顺带连通了旁边的隐藏房，仍算红钥匙。AI 只在隐藏房、超级隐藏房都找到后才用红钥匙，不受影响。
- **AI 怎么找**（`js/ai.js`）：一层结束后（找完或放弃），结果卡给出"AI 平均要消耗几颗炸弹、几次红钥匙"，点"看 AI 怎么找"在地图上一步步回放：AI 每一步看到的概率、它的选择（框出来）和结果，之前的步骤标上序号，可以单步、自动播放。
  - AI 只知道玩家知道的：看得见的地图、房间布局和门位，以及这一层有哪几种隐藏房（把联合后验限制到这些种类）。它先用炸弹，每次炸隐藏房或超级隐藏房概率最高、又挨着已知房间的墙；两者都找到后（忏悔+）用红钥匙，每次开最可能通到究极隐藏房的门位，没有门位直接挨着候选时，挑两格内候选最多的。
  - "平均"是在联合后验上精确求的期望：每一步按它会揭示的结果把假设分组，递归到底。在 400 局胎衣† 和 400 局忏悔+ 楼层上：AI 每层都能找全（没有卡住的假设），平均约 2.8 颗炸弹，忏悔+ 另加约 1.3 次红钥匙；实际回放的平均和期望一致。
  - 顺带修正了一条规则：炸过、什么都没有的墙仍然是门位，红钥匙可以在那里开红房间（原来会被排除，导致有的楼层找不到究极隐藏房）。撤销时恢复被覆盖的标记。
- **排行榜**（`js/scoreboard.js`）：分"今日"（今日挑战）和"总榜"（所有挑战），按游戏版本分开。每位玩家、每个游戏、每个种子、每层只记第一次的成绩。
  - 共享排行用 Supabase：在项目的 SQL Editor 里运行一次 [`web/scoreboard.sql`](web/scoreboard.sql)（建表、只许读和新增的权限、两个排行视图），再把项目 URL 和 publishable key（`sb_publishable_...`，旧项目是 anon key）写进 `rl/runs/macro/supabase.json`（`{"url": ..., "key": ...}`，不进 git）。`build_site.py` 和本地服务都会读它。没有这个文件时，成绩只存在当前浏览器里，页面会说明这一点。publishable key 只放在 `apikey` 头里（它不是 JWT）。
  - 已接入的项目：`evvufjkrmxdjootmgeyk`（2026-09-27）。核对过：两个视图可读；新增一条越界的分数会被表上的检查拒绝（说明写入权限和检查都生效，没有留下测试数据）。
  - 分数由浏览器计算和提交，懂行的人可以伪造；表上的检查只把分数限制在一层能拿到的范围内。提交失败会先存在本机，下次联网时补交。

    - 提交和排序：提交成绩时带上 `ms`；`hr_board_daily` 只在每层都有用时的玩家上求和，没有用时的排在同分的后面。
    - 数据库要先加列并更新视图（`web/scoreboard.sql` 开头的 `alter table` 和 `hr_board_daily`），2026-10-20 已运行并发布。还没加时，页面提交不带 `ms`、读榜也不带它。`tests/js/check_scoreboard.mjs` 用一个小的假 PostgREST 核对了排序、名次和这条退路；名次查询也在线上 10-18 的榜上只读核对过（17 个抽样位置全部一致）。
- **回看**（2026-10-20，按用户要求：完成了当天的今日挑战才能看）：
  - 每层今日挑战结束时，操作和成绩一起发出，存进 `hr_moves`。格式是 `b43 k57 …`（每一步算作炸弹还是红钥匙，加上格子），附带是否放弃（`play.js` 的 `movesText` / `parseMoves`）。之前玩完的今天和昨天的层，下次打开页面时补发（`main.js` 的 `sendMoves`）。
  - 这些操作就是当天的答案，所以表不给任何人读，只能通过 `hr_replay` 函数取。函数只把某一天的操作交给"用自己的秘密口令交满那天 7 层操作"的人。口令是浏览器里随机生成的，不显示在任何榜上，所以别人不能冒用排行榜上公开的玩家 id。没有账号，所以拦不住先用另一个身份交一局白卷的人，只是门槛高了很多。
  - 页面上：今日、昨日榜的那一天，本机完成了今日挑战时，名字可以点；没完成时，榜单上方提示完成后才能看。点名字进入那一天的今日挑战（本机自己已完成的那一局），一步步重放 TA 的操作。
    - 重放的样子和自己玩时一样（2026-10-25 起；原来套用 AI 回放的界面，地图上全是概率）：第 k 步显示 TA 走完前 k 步后看到的地图（空墙打叉、找到的房间、红房间），刚走的一步框出来、标序号；往前走一步时播放炸开的效果并弹出这一步的得失分。面板是"回看 · 名字"，步骤列表和自己的记录同一种写法（"炸 起点右3上2：空的 −25"），只列出已经重放的步，另有"到这里多少分"、⏭ 直接看结果和自动播放（`main.js` 的 `renderWatchBoard` / `renderWatchPanel`）。
    - "显示当时的概率"（默认关，记在本机 `hr-replay-probs`）：打开后地图上显示 TA 走下一步之前、按规则推算的概率，每一步下面标出"命中的机会"：按 TA 那一步之前看得到的信息，这一步能找到隐藏房的机会，在联合后验上精确算（`ai.js` 的 `playerReplay`）。
    - 换层继续看同一个人；可以在 TA 和 AI 之间切换；回看上线前玩的层显示"没有记录"。
  - 数据库要先运行 `web/scoreboard.sql` 末尾的 `hr_moves` 表、插入权限和 `hr_replay` 函数，再发布页面；否则补发的操作会被丢掉。`tests/js/check_scoreboard.mjs` 按这个函数的规则核对了排队、断网重发、口令和 7 层的门槛；`check_page.mjs` 把 AI 的走法当作玩家操作回放，核对结果一致。
- **地图**：房间图标的帧（13×12）比房间格子（9×8）大，原来图标也接收鼠标，所以隐藏房的悬停范围会超出它的格子；现在图标和格子贴图都不接收鼠标，由房间自己的格子（透明矩形）接收。窄房间：游戏的小地图贴图本来就是细长条，但特殊房间的图标会把它整个盖住，现在窄房间的图标画成一半大，细长条露在外面；"文字标签"模式下窄房间画成走廊。
- **反馈**：找到隐藏房时播放游戏里的发现隐藏房音乐（`music.xml` 第 85 首，`GridEntity_Door::TryBlowOpen` 0x2FC530 在炸开没去过的隐藏房时播放），以撒竖大拇指（玩家动画 `Happy`）并弹出得分；一层找完时加上游戏的竖大拇指音效（`sounds.xml` 268）。右上角可以静音，会记住。标题旁边的以撒也是这个动画的一帧。
- **速度**：
  - 生成器不再用 numpy（`isaac_macro/f32.py` 用 `struct` 做 float32 舍入；对 300 局双版本整局逐字段比对，结果和 numpy 版完全相同），浏览器少下载约 3 MB、少一步初始化。

## 关键结果与边界

历史 AB+ 引擎统计来自 5,200 层（第 1–8 层）。普通隐藏房：邻居最多优先首弹命中 30.4%、平均 2.82 弹；放置规则+布局证据首弹 88.6%、三弹内 98.0%、平均 1.20 弹。超级隐藏房的深度先验+布局证据首弹 76.7%、平均 1.42 弹。

这些是离线信息条件下的结果：布局证据的获取与合法可见性必须另行成立，不能把真实隐藏房位置或未探索布局直接送给策略。规则规划器的历史评估不含真实战斗；不能作为完整游戏策略成绩。

AB+ 与忏悔+ 的道具池、品质和机制不同，不可直接互换先验。J460 移植的历史状态是“离线主线完成、尚未与真实游戏全面核对”，不改写成原版一致性已通过。

## 从旧目标条件路线保留的语义

- 跨房自然继承血量、炸弹和资源；转场结束即可控制，不偷偷补血或空跑固定帧。
- 未清房离开是 exit，不是清房；真实楼层连接不能用彼此无关的 goto 房间伪装。
- 出题器/分析器可以知道完整地图，正式策略不能看到未知房间或隐藏信息。
- 若复现旧势函数塑形：`F=γΦ(s′)−Φ(s)`，真正终止 `Φ=0`；保证的是折扣总和，不是普通求和。炸弹改变地形时保留旧状态的旧势值，不能用新地图回算它。
- 旧 COMBAT/GOTO 的清历史、残差头与奖励配方只属于那条实验路线；不要沿用到当前跨房记忆策略。
